# 对外表达任务

`tasks/` 记录一次具体表达工作的目的、范围和完成边界。

一个任务至少应能回答：

- 面向谁表达什么；
- 为什么现在要做；
- 使用哪些已授权来源；
- 输出放在哪里；
- 什么条件下可以进入评审；
- 谁负责专业判断、确认和后续维护。

首个真实任务计划为“大工项目概览与当前进展”。当前只保留承载位置，不预填项目事实或演示数据。

## 任务循环

根 `AGENTS.md` 已接入共享 [任务循环](../vendor/suanhai-team-external-expression-infrastructure/harness/task-loop/ENTRYPOINT.md)。用户要求开始制作时，Agent 通过工具登记草案，未知项可先留待澄清；只读调查不创建任务。

每个工具管理的任务目录为 `tasks/<任务编号>/`：`task.json` 保存请求、简报、状态、反馈、产出引用及下一步，是唯一任务事实源；`task.md` 是工具生成的阅读视图。不要直接修改视图后当作完成状态已更新。

任务号可用于跨会话恢复。用户目标改变需重新对齐，局部反馈可直接迭代；本轮完成保留已确认产出，后续重新开启修订。任务记录与文件同步到新设备后才可在那里续作。

验证只在隔离测试 clone 中用 `--test` 创建，不能把合成反馈、演示作品或测试确认混入本仓真实任务。
