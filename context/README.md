# 项目上下文

`context/` 是大工项目对外表达任务的结构化入口。它保存足以让成员和 Agent 理解项目、判断表达边界和定位事实源的摘要，不复制源仓库、会议、聊天或附件全文。

## 建议读取顺序

1. [项目结构化理解](./project-structured-understanding.md)：项目由哪些核心对象构成、对象之间如何关联，以及事实和作品分别由哪里承载；
2. [项目概览](./project-overview.md)：项目是什么、为什么做、范围和不包含项；
3. [当前状态](./current-status.md)：截至最近一次材料的阶段判断、证据状态、风险和下一步；
4. [工作主线](./workstreams.md)：三条固定主线及其与对外表达的关系；
5. [来源登记](./sources.md)：每项摘要依据什么、处于什么状态、是否允许公开引用；
6. [表达边界](./expression-boundary.md)：public 资产仓库可以写什么、必须避免什么。

## 当前快照

本目录的第一版上下文由项目源仓库 `develop` 分支提交 `696d306` 以及 2026-10-23 第六次对外双周报和会议纪要整理而成。对外双周报是对外汇报稿，会议纪要是会后整理稿，均存在需要参会方或项目负责人核对的内容；本目录因此是**候选项目上下文**，不是替代源仓库的正式裁决。

## 状态标记

- **已确认**：有正式文件、合入代码、验收结果或明确责任人确认；
- **有证据但未验收**：有报告、日志、测试或会议材料，但尚未完成正式审查；
- **草稿或计划**：未来安排、候选方案或待执行事项；
- **待核对**：来源存在冲突、时效不足或责任人尚未确认。

每项重要主张都应保留来源和状态。未经授权的项目资料、客户材料、源码、二进制、账号、令牌、内网地址、原始群聊和大体积原始数据不进入 public 资产仓库。
