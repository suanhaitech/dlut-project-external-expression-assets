# 对外表达边界

> **文档状态**：public 资产仓库的候选边界说明
> **整理日期**：2026-10-28

本仓库用于承载大工项目的脱敏上下文、表达任务、作品、来源关联和评审记录。仓库为 public，文件进入仓库只能说明其被保存，不能说明技术结论已经验收或内容已经获得所有场景的发布许可。

## 1. 可以进入仓库的内容

- 已确认可用于项目表达的项目定位和阶段摘要；
- 经过必要脱敏、能够追溯来源的阶段性技术材料；
- 受众、用途、算例和条件清楚的图表、页面和汇报文字；
- 不含受限内容的任务、作品源稿、评审意见和确认记录；
- 对私有源仓库的抽象来源标识和事实状态。

## 2. 不得进入仓库的内容

- 合作方源码、二进制、未授权算例、原始实验数据和受限附件；
- 访问凭据、身份信息、内部网络定位、服务器和个人设备的本机绝对路径；
- 原始群聊、录音访问地址、联系方式和未脱敏会议材料；
- 未确认的合同承诺、报价、内部人员安排和资源细节；
- 只在内部讨论中出现、尚未核验或尚未获准使用的技术判断；
- 把单次测试、预测数据或同时改变多项配置的结果写成普遍性能结论。

## 3. 内容使用的四个条件

一项内容能否进入某次表达，需要同时判断四个条件：

| 条件 | 需要回答的问题 |
| --- | --- |
| 受众 | 面向项目内部、合作方、公开读者还是其他特定对象？ |
| 用途 | 用于内部讨论、阶段汇报、技术评审、验收说明还是公开展示？ |
| 内容范围 | 使用哪项事实、图表、数据、结论或计划，是否已脱敏？ |
| 授权 | 谁确认技术事实、谁确认表达内容、谁授予该受众和用途下的使用许可，许可是否有期限？ |

授权应按内容、受众、用途和时间记录。一次内部使用许可不能自动扩大为公开许可；某张图表获准使用，也不表示图表背后的全部原始数据可以公开。

## 4. 事实状态与表达强度

| 事实状态 | 推荐表达 |
| --- | --- |
| 已确认 | 说明结论、来源和适用条件 |
| 有证据但未验收 | 写成“阶段性观察”“当前材料显示”，同时保留限制 |
| 草稿或计划 | 写成“拟”“计划”“候选方案” |
| 待核对 | 标为待确认，不作为对外结论 |

“有报告”“有测试”“有会议纪要”“已提交代码”“检查通过”和“已生成作品”都是过程事实，不能单独推出技术验收、项目完成、客户接受或发布许可。

## 5. 作品发布前检查

1. 在任务记录中写明受众、用途、范围、完成标准和责任信息。
2. 为每项重要主张登记直接来源、版本、日期、适用条件和事实状态。
3. 对性能内容记录算例、软件版本、硬件、进程/线程、计时范围、正确性和限制。
4. 删除受限资料、原始数据、访问信息、个人信息和本机绝对路径。
5. 分别完成专业事实核查、表达质量评审和披露授权确认。
6. 记录授权主体、授权范围和有效期限；期限或受众变化时重新核对。

## 6. 常见边界错误

- 把源仓库的事实摘要写成资产仓库独立确认的结论；
- 把会后整理稿写成双方已经正式决策的文件；
- 把参考框架、候选架构或未来计划写成已定路线；
- 把局部算例的阶段性性能观察外推到全部模型；
- 把作品存在、版本提交或工程检查通过写成已获发布授权；
- 把 Agent 生成、整理或检查行为写成真人技术判断或责任确认。

工程检查只说明文件结构、链接或格式满足检查条件，不替代技术正确性、项目责任判断和特定用途的发布授权。
